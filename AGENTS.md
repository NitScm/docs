This document describes a set of rules and conventions maintainers use in this repo.

## PR structure

* PRs in this repo are kept to one commit only. Iterations on the PR
  should be folded into existing commit by amending.

## Commit message conventions

* Use an `Assisted-By:` footer (not `Co-Authored-By:`) to attribute LLM/agent involvement in commits
* The `Assisted-By:` footer must reference the actual model used, not a generic name
  * Example footer: `Assisted-By: anthropic/claude-opus-5`

* Commit messages must use a conventional commits prefix

* Commit messages must include a `Change:` footer with an alphanumeric, dash-separated identifier
  * Example footer: `Change: flatten-invert-check`

## Committing work

* Always build before committing:

  ```sh
  pnpm run build
  ```

  The build fails on a sidebar slug with no page, which is the most common way
  to break this site.

* **Never document behaviour you have not run.** Paste real output: run the
  command and copy what it printed. Invented output has been wrong here four
  times, each time in the direction of making things look safer or simpler than
  they are. If you cannot verify something, write what you did verify and say
  plainly what is unverified.

## Repo conventions

* pnpm, pinned by `package.json`'s `packageManager` field. `./dev.sh` selects
  Node from `.nvmrc` and installs when the lockfile is newer than
  `node_modules`.

* The sidebar in `astro.config.mjs` is hand-written, not autogenerated. Reading
  order matters: a new page needs its slug added there, and a slug with no page
  fails the build.

* The site is served under `/docs`. Write links **without** that prefix —
  `[x](/concepts/guards/)` — a rehype plugin in `astro.config.mjs` applies it at
  build time. `index.mdx` is the exception: component props and frontmatter are
  outside the Markdown pipeline, so it uses `import.meta.env.BASE_URL` and
  relative paths.

* Concepts explain why, guides explain how, reference is exhaustive and dull. A
  page that mixes the three serves none of them.

* `reference/` must match the code. Check a flag against `nit/cmd/`, a
  setting against `nit/internal/bootstrap/`, an error code against
  `nit/pkg/protocol/common.go`.

## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.

## Agentic work

* For creating temporary plans, files, and experiments, use the gitignored `.agents/work/` folder
  in the root of the repo
* Inside, create subfolders matching to current work topic
  * Example folder: `.agents/work/link-checker`
  * Example file: `.agents/work/link-checker/PROGRESS.md`
